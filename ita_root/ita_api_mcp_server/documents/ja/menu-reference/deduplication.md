# deduplication reference

OASEの重複排除設定。冗長構成の監視ツール（同じ監視対象を見ている複数の監視ツール）から届く同じ内容のイベントを、1件にまとめる。**まとめる対象の収集設定（`event_collection`）と、そのラベル付与設定（`labeling`）を先に作っておく必要がある**。

## 重複と判定される仕組み（重要）

イベントを受信したとき、次の条件をすべて満たす既存のイベントがあれば、そのイベントは新しいイベントにならず、**先に届いたイベントにまとめられる**（どの収集設定・エージェントから何回届いたかが、先着のイベントに加算される）。
- **冗長グループ内の別の収集設定**（または別のエージェント）から届いたイベントである。同じ収集設定から届いたイベント同士は、重複排除の対象にならない
- 先着のイベントが、まだ有効期限内（収集設定の`ttl`内）である
- ユーザーが付けたラベル（ラベル付与で付けたラベル）の値が、条件に従って一致する（下記）

まとめられたイベントは捨てられるのではなく、先着のイベントの記録として残る。ルールの判定には先着の1件だけが使われるため、対処も1回だけ動く。
- 重複排除は**設定を登録した後に受信したイベント**から効く。既に受信済みのイベントはまとめられない。

## condition_labels column と condition_expression column（判定条件）

| condition_labels | condition_expression | 重複と判定する条件 |
|---|---|---|
| 指定しない | 指定しない | ユーザーが付けたラベルが**すべて**一致したとき |
| 指定する | `is matched`（一致する） | **指定したラベルだけ**が一致したとき（他のラベルは見ない） |
| 指定する | `is ignored`（無視する） | **指定したラベルを除いた**残りのラベルがすべて一致したとき |

- `condition_labels`と`condition_expression`は、**両方指定するか、両方指定しない**。片方だけだと`条件を指定するには、ラベルと式の両方を入力する必要があります。`（MSG-160001）になる。
- `is matched`で指定したラベルは、**冗長グループのすべての収集設定のラベル付与設定に存在する**必要がある。無いと`ラベル付与メニューで、イベント収集先と条件ラベルが紐付けられていません。`（MSG-160002）になる。
- `is ignored`で指定したラベルは、冗長グループの**いずれかの**収集設定のラベル付与設定に存在すればよい（無いとMSG-160003）。
- 選び方の目安:
    - 監視ツールどうしでラベルが完全に同じになる → 条件なし（すべて一致）でよい
    - 監視ツールごとに値が違うラベルがある（例: 監視ツール側のイベントID、取得時刻をラベルにしているもの）→ そのラベルを`is ignored`にするか、同一性を表すラベル（ホスト・種別など）だけを`is matched`にする
    - どちらにするかは、ラベル付与設定（`labeling`）を`menu-filter`で確認し、各ラベルが監視ツールごとに同じ値になるかを根拠に提案すること。推測した場合はその旨を伝える。

## event_source_redundancy_group column（冗長グループ）

- 重複排除の対象にする収集設定を複数指定する。
- **1つの収集設定は、1つの重複排除設定にしか入れられない。** 既に他の重複排除設定で使っていると`冗長グループで指定されたイベント収集先は、他の重複排除設定で既に使用されています。`（MSG-160004）になる。登録前に`menu-filter`（`menu: "deduplication"`）で既存の設定を確認すること。

## 複数選択の項目の渡し方（重要）

`event_source_redundancy_group`と`condition_labels`は複数選択の項目で、**表示名のJSON配列を「文字列」にして**渡す。
```json
"event_source_redundancy_group": "[\"Zabbix監視イベント収集\", \"Zabbix監視イベント収集（2号機）\"]",
"condition_labels": "[\"_exastro_host\", \"alert_type\"]"
```
- **JSONの配列のまま渡すと、原因の分からない`System Error (999-99999)`になる。** 必ず文字列にすること。
- JSONとして読めない文字列は`JSON format is abnormal`になる。
- 表示名は`list-menu-info-pulldown`で確認する。`condition_expression`の値は`is matched`/`is ignored`（環境の言語設定によって表示名が変わるので、プルダウンの値をそのまま使う）。

## setting_priority column

- 整数。共通の収集設定・ラベルを含み、優先順位が同じ設定が複数ある場合は、重複排除設定名の昇順で適用される。通常は`1`でよい（省略時も`1`が入る）。

## 新規作成時の最小サンプル

```json
{
  "menu": "deduplication",
  "records": [{
    "type": "Register",
    "parameter": {
      "deduplication_setting_name": "Zabbix冗長構成の重複排除",
      "setting_priority": "1",
      "event_source_redundancy_group": "[\"Zabbix監視イベント収集\", \"Zabbix監視イベント収集（2号機）\"]",
      "condition_labels": "[\"_exastro_host\", \"alert_type\"]",
      "condition_expression": "is matched"
    }
  }]
}
```
