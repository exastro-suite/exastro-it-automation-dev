# Feature Overview
OASE is a feature that analyzes event information obtained from external sources and supports automating the response to those events.
The functional flow of OASE is as follows.
1. **Event Collection**
1. **Label Assignment**
Assigns configured labels to events received by ITA.
For details on the settings related to label assignment, refer to  and  .
1. **Evaluation**
Using the assigned labels, events are extracted (filtered) and it is determined whether they match the configured rules.
For details on the settings related to rule determination, refer to  and  .
1. **Action Execution and Notification**
When an event matches a rule, the configured action (Conductor and Operation settings) can be executed.
Notifications before and after an action is executed can also be configured from the Rule menu.

# Definition of Terms
- Term
     - Content
- Monitoring system
     - | A general term for software or services used to collect changes in system state.
- OASE
     - | Exastro OASE is software that supports monitoring and operational automation of systems.
It collects events generated by the monitoring system and executes appropriate actions based on defined conditions.
- Event
     - | Information on a change in system state (its occurrence) obtained from a configured target (monitoring system). ※
- TTL (Time To Live)
     - | The period (in seconds) during which an event obtained by the agent is treated as a target for rule evaluation. It is used for the following two purposes.
If an event occurs and that event is defined as a condition of multiple rules, Exastro OASE will attempt to operate so that the rule with the higher priority is applied.
- Label
     - | A property of an event that is assigned in a form (key and value format) that is convenient to use internally within OASE, based on the label creation and label assignment settings.
- Deduplication
     - | Even when multiple pieces of event information that are essentially identical are obtained, this can be configured so that only the first event is imported.
This is a feature for avoiding the handling of duplicate data when the event collection system or the OASE agent is made redundant.
- Filter
     - | The extraction of a unique event based on label conditions, or the target of such extraction. It plays the role of narrowing down which events are subject to rule determination, prior to the rule determination stage.
- Rule
     - | A condition for executing an arbitrary action or generating a conclusion event, created by combining filters.
- Action
     - | The specific response process executed on an event when it matches a defined rule.
- Evaluation
     - | The process in which collected events are extracted by a filter and it is determined whether they match the rule conditions,
- Conclusion event
     - | An event that occurs when a rule is matched.
- Type
     - Content
- New
     - | The state of having been collected but not yet detected by the evaluation function.
- Known
     - The state or target that has been detected by the evaluation function.
- Known (determined)
     - The state or target that has matched a rule.
- Expired
     - | A target excluded from rule evaluation for one of the following reasons.
- Unknown
     - | The state or target that was not extracted by a filter (not detected by the evaluation function).
- Item name
     - Description
- New event (on receipt)
     - | Notified at the point the event is received.
However, if deduplication settings are enabled, events determined to be identical are not notified.
- New event (on consolidation)
     - | Notified when the received event is consolidated.
- New event (before determination)
     - | Notified for events that became a target of rule determination.
- Known event (at determination)
     - | Notified when the event matches one of the rules.
- Known event (TTL expired)
     - | Notified for events for which the TTL has expired.
- Unknown event
     - | Notified for events that did not match any rule or condition.
